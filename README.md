# 知序 · 论文投稿管理

可直接运行的中文本机 Web 系统。使用 Java 17+ 和原生 HTML/CSS/JavaScript。默认使用无第三方依赖的加密文件存储，也支持 MySQL 8.0.16+ 的关联表存储（需要 MySQL 服务和 JDBC 驱动）。

## 启动

Windows 双击项目根目录的 `start.cmd`，然后在浏览器打开 **http://127.0.0.1:8080**。

首页提供“登录”“注册”“修改密码”三个入口，默认显示登录页。注册页始终可以填写新账号：账号需要 3–64 个字符，以字母或数字开头，支持字母、数字、下划线、点、@、加号和减号；密码需要 10–128 个字符。提交后校验账号是否重名，不会因为系统中已有其他账号而禁止注册，也不会在未输入账号时断言用户已经注册。**没有默认密码；管理密码也用于加密数据，遗忘后无法找回。**

每个账号拥有独立工作空间，客户、论文、投稿、收支和备份均按当前登录账号隔离。新注册账号从空白工作台开始，已有账号和业务记录保留。同一浏览器同一站点使用一个当前账号；不同浏览器或独立浏览器环境可以同时登录不同账号。

首页“修改密码”需要验证登录账号和原密码，修改成功后仅该账号的已有登录失效，其他账号可以继续使用。登录后的首页右上角也可直接进入修改密码；旧备份仍使用备份时的密码解锁。

也可以在项目根目录手动执行：

```powershell
javac -encoding UTF-8 --release 17 -d out src/*.java
java -cp "out;lib/*" Main
```

IntelliJ IDEA：设置项目 JDK 为 17 或以上，运行 `src/Main.java` 中的 `main`。工作目录设为项目根目录。

端口被占用时可改成 8088：

```powershell
java "-Dapp.port=8088" -cp "out;lib/*" Main
```

服务只需启动一次。若已通过 `start.cmd` 或命令行启动，可直接在浏览器访问；切换到 IDEA 运行前，先在原启动窗口按 Ctrl+C 关闭旧服务。重复使用同一数据目录时，程序会提示“知序已经在运行”并退出。修改端口不会解除同一数据目录的占用；旧服务停止后即可重新运行，无需删除 `app.lock` 或数据文件。

## 阿里云服务器部署包

执行 `python scripts/package_release.py`，在 `dist/` 生成适用于 Java 17+ 的 ZIP 与 tar.gz 部署包及 SHA-256 校验文件。包内包含已编译程序、前端、MySQL 驱动和 Linux 部署脚本，不含本机连接密码、密钥或业务数据。Linux 的安装、自启、MySQL 配置、HTTPS 反向代理和数据迁移见 [部署说明](deploy/DEPLOY.md)。程序保持仅监听本机，通过 SSH 隧道或附带的 Nginx HTTPS 模板访问，支持多账号独立工作空间。

应用与存储可一起部署到同一台 ECS，或使用 ECS 加 RDS 内网数据库。迁移全部 MySQL 账号和业务时，使用 `scripts/backup_mysql.py` 将整库和匹配的 `database.key` 一起导出；部署包内包含备份工具、MySQL 建库模板及每日定时备份示例。具体导出、校验、恢复和云端切换见 [MySQL 全量迁移说明](deploy/MYSQL-MIGRATION.md)。

## 业务模块与关联

侧栏依次为论文总览、客户管理、论文管理、投稿管理、待跟进事项、收支管理及数据与设置，保留原有浅色与墨绿页面风格。总览用于查看整体进展，客户管理维护客户信息，论文管理维护论文及写作安排，投稿管理记录每次投刊。“新建论文（全包）”“新建论文（半包）”统一位于论文管理页，其他模块按业务场景提供查看、筛选和跳转。客户详情可跳转到该客户的论文列表，新建时预选该客户；待跟进事项只展示已有论文的跟进计划。

推荐使用顺序：

1. 在“客户管理”建立姓名、手机号、邮箱、微信、单位等基本资料。同名客户可分别建立，以编号区分。
2. 在“论文管理”中按服务内容选择入口：“新建论文（半包）”用于客户提供文章，录入论文、客户、服务费用和拟投期刊；“新建论文（全包）”另外记录写作人、写作状态、交稿日期、稿酬及约定定金。全包和半包均在论文管理中展示，可按服务类型、客户、写作状态和论文建档日期筛选并导出；写作进行中、逾期未交、已交稿及稿酬统计仅包含全包论文。
3. 在论文详情“收支明细”登记实际定金和尾款；约定金额与实际收付分别记录。
4. 在“投稿管理”选择关联文章，为每次投稿单独保存投稿题目、期刊、系统、账号密码、绑定邮箱手机号、投稿/结束/发表日期和状态。改投时新增记录，原投稿完整保留。
   列表操作为“编辑、改投、删除、详情”。点击“改投”直接关联该论文并沿用选中记录的投稿题目，新期刊、账号与日期按本次投稿填写；保存后新增一条当前投稿，原投稿与收支保留。论文管理和投稿详情中也提供“改投论文”入口。删除需要确认，仅删除选中的一次投稿及其投稿凭据，保留论文、其他投稿和收支。详情中的“投稿密码”指期刊投稿系统的密码，与本系统的登录密码分别保存。
   改投表单上方显示该论文的全部投稿历史，包括期刊、当时题目、状态、投稿/结束/发表日期、时长与备注，并标记当前记录和此次改投来源。历史可折叠、滚动查看；待投稿记录明确显示尚未投稿。输入已有同名期刊时会提示既往记录，忽略英文大小写、空格及全半角差异；确需再次向同一期刊投稿时可以继续保存新记录。同名论文仍按各自编号分别累计历史。
5. 在客户详情查看关联论文、已发表题目和期刊，以及服务费用、已收款与未收款。客户改名、写作题目修改后，关系通过 UUID 保持，不靠文本匹配。

客户费用按论文汇总，不因多次投稿重复计费。写作题目与各次投稿题目可不同，均通过同一个论文编号关联。

论文、客户、投稿及收支保存成功后，自动关闭表单并更新对应列表与统计；保存失败时保留填写内容并提示原因。半包没有写作稿酬，投稿等费用登记为“其他支出”。旧论文保留原有写作流程，按全包兼容读取。

论文管理列表的操作列提供“删除论文”。点击后显示论文题目、编号及关联投稿、收支数量，二次确认后删除该论文及其写作安排、全部投稿与投稿账号资料、历史和收支记录，并重新计算客户及财务统计；客户档案和其他论文保留。删除使用版本校验，遇到其他页面已更新该论文时提示刷新后重试。删除前建议下载备份。

客户信息可记录“合作开始日期”，在新建或编辑客户时填写实际开始合作的日期，支持补录、修改和清空；列表、客户详情及客户汇总导出均包含该日期。它与档案创建时间分别保存，旧客户默认留空，不会推断为建档当天。

投稿时长为实际投稿日至结束/录用日期的天数；未结束计算到当天。已发表的成果另记发表日期。录用、拒稿、撤稿、发表时未填结束日期则自动记录当天；补录历史时可输入真实日期。旧记录没有可靠结束日期时保留未知，不会假定今天为结束日。

写作任务可按状态、客户、开始日期筛选，逾期未交任务单独展示；客户信息支持归档。有论文关联的客户禁止直接删除，可先调整论文归属或归档。

## 已实现

- **论文档案**：题目、作者、客户/委托人、写作者、期刊、投稿系统及网址、投稿日期、跟进日期、备注。
- **账号资料**：投稿账号、投稿密码、绑定邮箱、绑定手机号；密码默认不随档案接口返回，需在详情中点击显示，30 秒后自动隐藏，切换后台时也会隐藏。
- **投稿进度**：草稿、待投稿、已投稿、审稿中、修改中、已录用、已发表、已拒稿、已撤稿；修改期刊、系统、网址、日期或状态时保留变更历史。
- **费用约定**：约定向客户收取的总额，以及约定向写作者支付的稿酬总额。
- **实际流水**：收取定金、收取尾款、其他收入、支付定金、支付尾款、其他支出，支持多次登记、删除错误流水，记录日期、收付方式和备注。
- **自动统计**：已收、已付、未收、未付、现金净额；金额按整数分存储计算。
- **查询**：按题目、编号、作者、客户、写作者、期刊、系统、账号、邮箱、手机号和备注搜索，支持状态、日期、待跟进和归档筛选及分页。
- **跟进计划**：设置下次跟进日期后，到期的未发表、未撤稿论文进入待跟进提醒。
- **导出**：按当前筛选导出 UTF-8 BOM CSV，可用 Excel 打开；台账包含定金、尾款等分类合计，流水可单独导出。CSV 不包含投稿账号、密码、绑定邮箱和手机号；客户汇总导出也不含客户联系方式。备注等自由文本会原样导出，请自行避免在备注中填写敏感信息。
- **备份恢复**：下载完整加密备份并通过界面恢复；恢复需要备份时的密码，替换全部记录，恢复后保留当前系统登录账号与管理密码。
- **访问保护**：新账号注册、账号与密码登录、退出、修改管理密码及账号数据隔离；8 小时会话、HttpOnly/SameSite Cookie、CSRF 校验、登录限流、来源校验、仅监听本机地址。

## 收支计算

例如，一篇论文约定应收 8,000 元，约定稿酬 3,000 元：

1. 先登记“收取定金”2,000 元、“支付定金”1,000 元。
2. 系统显示已收 2,000、未收 6,000、已付 1,000、未付 2,000 元。
3. 后续分别登记收取尾款与支付尾款，系统自动汇总。

未收 = max(0, 约定应收 − 已收定金 − 已收尾款)，未付 = max(0, 约定稿酬 − 已付定金 − 已付尾款)。其他收入、其他支出单独统计，不抵扣合同尾款或稿酬尾款，例如期刊费用不会误抵写作者稿酬。实际定金和尾款合计超过约定时会显示提示，不会阻止记录。累计已收、已付与现金净额包含全部流水；现金净额 = 全部实际收入 − 全部实际支出，不代表最终利润。

收支管理默认展示“应收应付”，按论文列出约定应收、已收定金尾款、待收款，以及约定稿酬、已付稿酬、待付稿酬；即使尚未登记实际流水，也能核对待收待付的来源。点击汇总卡片中的明细入口可查看对应收入、支出或全部流水，或进入论文“收支明细”核对并登记款项。汇总卡片统计全部论文，搜索和流水日期筛选只影响下方明细；应收应付按当前费用约定统计，不使用收支日期筛选。应收应付与实际流水可分别按当前筛选导出。

## 数据位置与备份

实际数据位于项目根目录：

```text
data/
  papers.vault       首个账号或旧版账号的加密数据
  papers.vault.bak   该账号上一次写入前的加密副本
  primary-account.id 首个账号名的 SHA-256 索引，不含密码
  accounts/         其他账号，按账号名 SHA-256 分目录保存独立的 papers.vault
  app.lock           进程锁文件，防止同一数据目录被两个实例同时写入
```

采用 AES-256-GCM 认证加密，使用随机盐和 PBKDF2-HMAC-SHA256（310,000 次）从管理密码派生密钥。论文及账号资料整体加密，采用临时文件写入后替换；每次写入前保留上一份加密数据。已有数据目录不要删除。

在“数据与设置”下载备份；恢复前先下载当前数据。旧备份仍使用当时的密码，即使后来修改了管理密码。紧急恢复 `.bak` 可以通过恢复窗口选择该文件，或先关闭服务、另存当前文件后，再用备份替换 `papers.vault`。

每个账号最多 10,000 篇论文，每篇最多 1,000 笔流水；每个加密数据文件最大 8MB，单笔及约定金额最大 100 万元。数据量增大时适合后续迁移到关系数据库。旧版仅使用管理密码的数据文件，首次用原密码及新账号登录时会绑定该账号；其后必须使用绑定账号登录。旧版根目录加密文件没有账号索引时，需要原账号先登录一次以建立索引，之后可以继续注册新账号，原加密文件不移动。恢复备份只替换当前账号的记录，不更改登录账号和密码。将另一账号的备份导入 MySQL 时会重新分配业务 UUID 并保留内部关联，避免与原账号记录冲突。数据目录可通过 `-Dapp.data=绝对路径` 指定，静态资源根目录可通过 `-Dapp.root=项目绝对路径` 指定。

当前版本支持多账号独立使用，程序仅监听 `127.0.0.1`；可按部署说明通过 SSH 隧道或 Nginx HTTPS 反向代理远程访问，不含团队共享空间、多人角色分工、附件上传、自动抓取期刊状态和邮件/短信提醒。投稿账号密码为人工登记，不会登录外部期刊系统。登录后的解密数据和密钥会保留在服务进程内存中，退出会撤销浏览器会话；关闭服务会释放进程内存。

## MySQL 存储

MySQL 模式沿用现有的客户、论文、投稿、收支及备份界面，业务数据分别保存在关联表中。每个注册账号拥有独立的工作空间和空间管理员身份，所有业务查询与修改绑定当前会话所属空间。旧账号保留原空间与数据；其他角色和团队共享授权尚未启用。服务仍只监听本机。

1. 准备 MySQL 8.0.16 或以上版本，将官方 MySQL Connector/J 驱动 JAR 放入 `lib/`，下载方式见 [驱动说明](lib/README.md)。第三方 JAR 不提交到仓库，新克隆项目需要自行准备。
2. 将 `config/application.example.properties` 复制为 `config/application.properties`，填写数据库地址、端口、库名、账号和密码，并设置 `app.storage=mysql`。真实配置已加入忽略列表，不要提交连接密码。
3. 双击 `start.cmd` 启动。启动器已包含 `lib/*` 的驱动路径；IDEA 项目也已配置 `lib` 目录作为依赖。手动启动时使用以下命令：

   ```powershell
   javac -encoding UTF-8 --release 17 -d out src/*.java
   java -cp "out;lib/*" Main
   ```

数据库不存在时，程序会尝试创建指定数据库；也可以由管理员预先创建。首次启动执行 [V001 初始化脚本](db/mysql/V001__initial_schema.sql)，只创建 `lw_` 前缀表，不删除已有表。数据库连接账号需要该库的建表、索引、外键及业务读写权限；自动建库还需要建库权限。脚本记录 SHA-256 校验，执行过的脚本不要直接修改。数据库连接失败时会停止启动，不会自动改写到文件存储。

升级时自动执行 [V002 合作开始日期脚本](db/mysql/V002__customer_cooperation_date.sql)，在 `lw_customer` 增加可为空的 `cooperation_started_at DATE` 字段，保留所有原客户数据。连接账号还需要该表的 `ALTER` 权限。该业务日期不做时区转换。

[V003 服务类型脚本](db/mysql/V003__paper_service_type.sql) 为 `lw_paper` 增加 `service_type`，区分全包和半包；旧论文默认全包以保留写作记录，半包不生成 `lw_writing_task`。该升级需要 `lw_paper` 的 `ALTER` 权限。

配置优先级为 Java `-D` 参数、环境变量、配置文件、默认值。支持 `APP_STORAGE`、`DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USERNAME`、`DB_PASSWORD`、`DB_SSL_MODE`、`DB_KEY_FILE`；可用 `-Dapp.config=配置文件绝对路径` 指定配置文件。远程数据库应使用可信证书和 `VERIFY_IDENTITY`；本机 MySQL 若提示 RSA 公钥获取受限，可配置受信任的 TLS，或仅在受信任的本机连接中设置 `db.allowPublicKeyRetrieval=true`。

### 旧文件迁移

切换前先停止旧服务并下载加密备份。MySQL 中尚无本系统成员且 `data/papers.vault` 存在时，登录页会要求使用原账号和管理密码。成功验证后，程序会：

- 在 `data/backups/pre-mysql-日期时间.vault` 保存原始加密文件副本；原 `papers.vault` 保持原样。
- 在一个数据库事务中导入客户、论文、写作、多次投稿、凭据、收支及历史，保留业务 UUID 和金额。
- 将原账号设为当前空间管理员，并记录导入文件的 SHA-256。后续登录读取数据库，不重复导入旧文件。

原密码或账号不正确不会导入；数据库已初始化时，不会用旧文件覆盖现有账号和业务记录。空数据库且没有旧文件时，首次打开仍由用户设置账号与管理密码，没有默认应用账号或密码。导入后，在界面核对论文和客户数量、已收已付及投稿记录，再使用数据库继续工作。

### MySQL 数据保护与回退

登录密码保存为带随机盐的 PBKDF2-HMAC-SHA256 哈希；投稿密码使用独立 AES-256-GCM 密钥加密，并绑定对应投稿 UUID。客户资料、题目、账号名称和金额等业务列按关系型数据库的常规方式保存，并非整库加密。默认密钥位于 `data/database.key`，可用 `db.keyFile` 指定。**备份数据库时必须同时保管对应密钥文件**；密钥缺失或不匹配时服务会拒绝启动，不能用新密钥替换已有数据库的密钥。

“下载加密备份”仍生成与文件模式兼容的 `.vault`，业务数据和投稿密码整体加密，可通过恢复界面在两种模式之间迁移。恢复只替换业务记录，保留目标安装的登录账号和管理密码。修改管理密码不改变数据库的独立投稿密钥，旧备份仍使用下载备份时的密码。单份备份导入仍限制为 8MB，当前论文与流水数量上限保持不变。

如需回退，可先下载 MySQL 模式中的最新加密备份，停止服务，设置 `app.storage=file` 后启动，再从界面恢复该备份。直接切回文件模式只会读取之前保留的文件，不会自动包含迁移后新增的数据库记录。不要同时运行两个模式来维护同一套业务。

## 升级与多人上线准备

旧版 schema=1 数据在登录时自动升级为 schema=2，保留原有账号、密码、论文、收支及投稿历史，并从原客户名称生成关联客户、从原投稿字段生成一条投稿记录。升级前文件保留在 `data/papers.vault.bak`；旧版备份恢复时也会转换。当前版本的客户、写作和多次投稿都会进入完整加密备份。

后续多人上线的角色矩阵、数据库表关系、空间隔离、字段权限、密钥拆分及迁移验收见 [多人上线设计](docs/多人上线设计.md)。当前已经提供 MySQL 关联存储及旧文件迁移，尚未启用多人权限和用户管理；远程访问按部署说明配置 SSH 隧道或 HTTPS 代理。切换存储不等于获得多人角色隔离。

## 验证

```powershell
python -m unittest discover -s tests -v
node --test tests/frontend.test.cjs
node --check web/app.js
node --check web/business.js
```

测试使用独立临时数据目录和本机随机端口，不接触 `data/`，覆盖初始化与访问控制、字段校验、金额汇总、版本冲突、凭据隔离、备份恢复、改密、重启持久化和请求保护。

MySQL 集成测试可按需启用：

```powershell
$env:RUN_MYSQL_TESTS='1'
# 如未自动找到 MySQL 安装目录，指定包含 mysqld.exe 的 bin 目录：
# $env:MYSQL_TEST_BIN='C:/Program Files/MySQL/MySQL Server 8.4/bin'
python -m unittest discover -s tests -p test_mysql.py -v
```

测试自行初始化 `.test-data/` 下的临时 MySQL 数据目录，在随机本机端口启动独立实例，结束后关闭并清理。不会连接已安装的 MySQL 服务或读取真实数据库连接密码。覆盖实际关联表读写、凭据密文、旧文件迁移、备份跨模式恢复和重启持久化。
