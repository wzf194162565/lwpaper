# 知序 · 论文投稿管理

可直接运行的中文本机 Web 系统。使用 Java 17+ 和原生 HTML/CSS/JavaScript。默认使用无第三方依赖的加密文件存储，也支持 MySQL 8.0.16+ 的关联表存储（需要 MySQL 服务和 JDBC 驱动）。

## 论文文件与版本

新建或编辑全包、半包论文时可选传 DOC、DOCX、PDF，也可先建档再补文件。在论文详情的“文件与版本”中上传修改稿、填写修改说明、查看及下载任意历史版本；同名文件仍生成 V1、V2 等独立版本。新增投稿、编辑投稿及改投时可选择本次实际使用的稿件，后续新稿不会改变历史投稿的版本关联。

默认单文件 50MB；可在配置中设置 `app.fileMaxMb=50`（范围 1–200），或使用 `APP_FILE_MAX_MB`、`-Dapp.fileMaxMb=50`。每账号稿件总量上限 512MB，每篇论文最多 200 个版本。系统校验格式和实际文件内容，支持上传进度、失败重试；删除论文同时删除其稿件文件，其他论文及账号的文件保留。

正文使用 AES-256-GCM 加密后独立存入私有目录，数据库或加密业务文件只记录元数据。文件模式保存在当前账号数据目录的 `attachments/`，MySQL 模式为 `data/attachments/<workspace UUID>/`；各目录包含匹配的 `files.key`。下载必须登录并通过论文归属校验，不能通过静态 URL 直接读取磁盘文件。

“数据与设置”在有稿件时下载 ZIP 完整备份，内含密码加密的业务记录及加密稿件；恢复支持 ZIP 和旧版 `.vault`，可在文件/MySQL 模式间迁移。ZIP 本身不使用通用压缩软件密码，其内部内容由系统加密；请在系统中输入备份时的管理密码恢复。业务记录仍受原有 8MB 限制，稿件容量独立计算。恢复替换当前账号全部记录及稿件，保留当前登录账号与密码。

整库迁移需连同 `database.key` 和整个 `attachments/` 一起备份；参见 [MySQL 全量迁移](deploy/MYSQL-MIGRATION.md)。版本管理由用户上传稿件及填写说明完成。

## 启动

Windows 双击项目根目录的 `start.cmd`，然后在浏览器打开 **http://127.0.0.1:8080**。

首页提供“登录”“注册”两个入口，默认显示登录页。注册页始终可以填写新账号：账号需要 3–64 个字符，以字母或数字开头，支持字母、数字、下划线、点、@、加号和减号；密码需要 10–128 个字符。提交后校验账号是否重名，不会因为系统中已有其他账号而禁止注册，也不会在未输入账号时断言用户已经注册。**没有默认密码；管理密码也用于加密数据，遗忘后无法找回。**

每个账号拥有独立工作空间，客户、论文、投稿、收支和备份均按当前登录账号隔离。新注册账号从空白工作台开始，已有账号和业务记录保留。同一浏览器同一站点使用一个当前账号；不同浏览器或独立浏览器环境可以同时登录不同账号。

修改管理密码需先登录，在“数据与设置”中验证当前密码后更新，也可通过登录后的首页右上角进入。修改成功后仅该账号的其他页面需重新登录，其他账号可以继续使用；旧备份仍使用备份时的密码解锁。

也可以在项目根目录手动执行：

```powershell
javac -encoding UTF-8 --release 17 -d out src/*.java
java -cp "out;lib/*" Main
```

IntelliJ IDEA：设置项目 JDK 为 17 或以上，运行 `src/Main.java` 中的 `main`。工作目录设为项目根目录。

端口被占用时可改成 8088：

```powershell
java "-Dapp.port=8088" -cp "out;lib/*" Main
```

服务只需启动一次。若已通过 `start.cmd` 或命令行启动，可直接在浏览器访问；切换到 IDEA 运行前，先在原启动窗口按 Ctrl+C 关闭旧服务。重复使用同一数据目录时，程序会提示“知序已经在运行”并退出。修改端口不会解除同一数据目录的占用；旧服务停止后即可重新运行，无需删除 `app.lock` 或数据文件。

## 阿里云服务器部署包

执行 `python scripts/package_release.py`，在 `dist/` 生成适用于 Java 17+ 的 ZIP 与 tar.gz 部署包及 SHA-256 校验文件。包内包含已编译程序、前端、MySQL 驱动和 Linux 部署脚本，不含本机连接密码、密钥或业务数据。Linux 的安装、自启、MySQL 配置、HTTPS 反向代理和数据迁移见 [部署说明](deploy/DEPLOY.md)。程序保持仅监听本机，通过 SSH 隧道或附带的 Nginx HTTPS 模板访问，支持多账号独立工作空间。

应用与存储可一起部署到同一台 ECS，或使用 ECS 加 RDS 内网数据库。迁移全部 MySQL 账号和业务时，使用 `scripts/backup_mysql.py` 将整库和匹配的 `database.key` 一起导出；部署包内包含备份工具、MySQL 建库模板及每日定时备份示例。具体导出、校验、恢复和云端切换见 [MySQL 全量迁移说明](deploy/MYSQL-MIGRATION.md)。

## 业务模块与关联

收支管理提供“统计年度”和“利润归属”筛选，默认本年度、按结清年度。累计收款、付款和净现金流按实际流水发生日期归集，包含跨年论文的当年收付款及退款、退回。当前待收服务费、待付稿酬、版面费和预计净利润按论文建档年份归集，不表示历史年末余额。净利润仅统计已结清论文，默认按最后一笔实际收付或终止结算日期的年份归属，也可切换为按建档年度归属；修改账目后报表随当前记录重新计算。利润明细逐篇展示服务收入、稿酬、我方版面费、其他净收支及净利润。版面费尚未确认的论文单列待核算；年度汇总、利润明细和流水均可导出，明细及导出遵循所选年度。


版面费在录入论文的同一表单中填写，保留“待确认、我方承担、无版面费、作者自理版面费”；我方承担时同时填写金额，尚不清楚是否收取或金额时选择待确认，利润显示待核算。我方承担的版面费包含在服务报价中，作为成本逐笔登记实际支付或退回；作者自理时，由作者自行支付，不包含在报价中，也不计入我方成本或流水。修改承担方式及金额只改变约定，不自动修改历史流水；若修改后已付超过应付，会显示待退回金额，真实退款另行登记。改投新期刊时须在同一投稿表单重新确认版面费，投稿与费用约定一起保存并更新预计利润；旧约定变更留存历史，不推断历史其他支出的用途。

预计利润 = 服务报价 − 总写作稿酬 − 各次投稿最终由我方承担的版面费 − 其他支出 + 其他收入。写作定金与尾款合计为总稿酬；客户定金与尾款只是分期收款，不重复扣作成本。每次投稿分别保存版面费约定、实际净付、待付和待退；改投的新期刊单独核算，不抵扣旧期刊款项。已付款不退时，可确认该期刊最终成本并填写核对依据；真实退款仍需另行登记。升级前无法确定期刊归属的历史费用保留为“历史汇总待核对”，不会猜测归属。费用约定未确认时利润显示“待核算”；全部客户款、写作稿酬和各期刊版面费结清后才显示已结清利润。终止服务后仍分别跟踪各期刊成本。

后续新增客户定金、尾款及写作稿酬流水均校验剩余约定金额，防止超额和重复收付；已有历史超额流水保留原金额，可继续核对处理。费用约定调整不能掩盖已经发生的客户收款。版面费流水必须选择对应期刊；改投前一期刊已有版面费实付时，须先完成旧期刊的成本结算，保留旧账，再新建改投。

在投稿管理的新增或编辑投稿表单中，通过“投稿状态”选择“终止服务”。填写终止日期、原因、客户最终应承担的服务费及写作者最终应得稿酬并确认后，终止整篇论文的服务（含全部投稿），停止常规写作、投稿推进和跟进提醒。选择该选项本身不会保存投稿或终止服务；“返回投稿”保留原表单未保存的内容，右上角 × 直接关闭。服务终止与期刊的“已撤稿”独立：原投稿状态、写作进度、稿件、费用约定及收支流水均保留；该客户的其他论文照常处理。终止后的论文可在论文管理及投稿管理的“服务已终止”中查看，投稿列表保留终止前状态，导出附带服务状态、终止日期与原因。

收支流水按实际收付登记。冲销用于更正录错，须填写原因并确认不是实际退款；系统追加一条与原记录等额、方向相反的冲销，原流水始终保留。随后可重新登记正确流水并关联冲销的原编号。真实客户退款、稿酬退回或期刊退款必须另登记实际反向收支，不用冲销代替。每笔流水显示经手账号、日期、收付方式及冲销关联，并记录收支、冲销、费用调整和凭证操作。支持上传加密的 PDF、PNG、JPG 或 Word 付款/收款凭证，并固定关联对应流水。已有流水无法补造历史经手人，显示为“历史记录”。论文删除入口始终保留，确认后清除论文及其收支、财务记录和附件；终止服务则保留档案与财务记录，账务更正使用冲销。终止结算、冲销与凭证随备份恢复；MySQL 自动执行 V008–V010。

侧栏依次为论文总览、客户管理、论文管理、投稿管理、待跟进事项、收支管理及数据与设置，保留原有浅色与墨绿页面风格。总览用于查看整体进展，客户管理维护客户信息，论文管理维护论文及写作安排，投稿管理记录每次投刊。“新增（全包）”“新增（半包）”统一位于论文管理页，其他模块按业务场景提供查看、筛选和跳转。客户详情可跳转到该客户的论文列表，新建时预选该客户；待跟进事项只展示已有论文的跟进计划。

推荐使用顺序：

客户管理按“客户 → 论文 → 作者”查看：一位客户可以关联多篇论文，每篇论文可以填写多位作者。客户列表只显示关联论文及已发表篇数，点击论文数量可直接查看该客户的论文；客户详情分为“客户资料”和“关联论文”两个页签，资料页只保留联系方式、费用汇总和备注；论文页每页显示 3 篇，搜索栏与分页栏固定，仅列表区域滚动，支持按题目、编号或作者搜索以及投稿状态筛选（全部投稿状态、草稿、待投稿、已投稿、审稿中、修改中、已录用、已发表、已拒稿、已撤稿），与论文总览共用状态定义，按论文当前投稿状态判断。每篇论文展示最新发表摘要，完整投稿和发表记录可点“投稿与成果”查看。每篇论文单独展示作者，超过 3 位时可展开全部姓名，不把不同论文的作者合并成客户名单。论文篇数、已发表篇数和费用均按论文统计，不因作者人数增加而重复累计；客户汇总导出保留论文及费用统计，论文档案导出保留每篇论文的作者。多位作者可用顿号、逗号、分号或换行分隔，无需建立独立作者档案。不同登录账号的数据保持隔离。

论文管理顶部统计卡片只展示汇总数据，样式与其它模块一致。通过下方“全部论文”“写作进行中”“逾期未交”“待付稿酬”等分类查看对应论文；待付稿酬只包含尚未付清稿酬的全包论文，列表显示合计金额，可进入每篇论文的收支明细。导出遵循当前筛选结果。

1. 在“客户管理”建立姓名、手机号、邮箱、微信、单位等基本资料。同名客户可分别建立，以编号区分。
2. 在“论文管理”中按服务内容选择入口：“新增（半包）”用于客户提供文章，录入论文、客户、服务费用、约定收款定金和拟投期刊，约定尾款按服务费用减定金自动计算；“新增（全包）”另外记录写作人、写作状态、交稿日期、稿酬及写作定金。收款定金不能超过服务费用，与写作定金分别保存；填写约定金额不会生成实际收支。全包和半包均在论文管理中展示，可按服务类型、客户、写作状态和论文建档日期筛选并导出；写作进行中、逾期未交、已交稿及稿酬统计仅包含全包论文。
3. 全包论文的表单按“确认稿酬约定 → 登记实际已付款”填写：录入约定总稿酬、约定定金，约定尾款自动计算；已付款可同时填写实际定金、尾款及各自支付日期，勾选已实际支付后与论文一起保存。编辑已有论文时显示累计已付，下方只填写本次新增金额，避免重复记账。也可在列表或论文收支明细点击“登记定金”“登记尾款”，默认填入剩余约定金额，核对日期和金额后确认。待付稿酬实时预览为“总稿酬 − 实际已付定金 − 实际已付尾款”，以 0 为下限。只录入约定不会生成付款，其他支出不抵扣稿酬。新流程校验本次支付不超过剩余约定金额；修改费用约定不能低于对应累计已付，需要更正时先核对实际流水。
4. 在“投稿管理”选择关联文章，为每次投稿单独保存投稿题目、期刊、系统、账号密码、绑定邮箱手机号、投稿/结束/发表日期和状态。改投时新增记录，原投稿完整保留。
   列表操作为“编辑、改投、删除、详情”。点击“改投”直接关联该论文并沿用选中记录的投稿题目，新期刊、账号与日期按本次投稿填写；保存后新增一条当前投稿，原投稿与收支保留。论文管理和投稿详情中也提供“改投”入口。删除需要确认，仅删除选中的一次投稿及其投稿凭据，保留论文、其他投稿和收支。详情中的“投稿密码”指期刊投稿系统的密码，与本系统的登录密码分别保存。
   改投表单上方显示该论文的全部投稿历史，包括期刊、当时题目、状态、投稿/结束/发表日期、时长与备注，并标记当前记录和此次改投来源。历史可折叠、滚动查看；待投稿记录明确显示尚未投稿。输入已有同名期刊时会提示既往记录，忽略英文大小写、空格及全半角差异；确需再次向同一期刊投稿时可以继续保存新记录。同名论文仍按各自编号分别累计历史。
5. 在客户详情查看关联论文、已发表题目和期刊，以及服务费用、已收款与未收款。客户改名、写作题目修改后，关系通过 UUID 保持，不靠文本匹配。

客户费用按论文汇总，不因多次投稿重复计费。写作题目与各次投稿题目可不同，均通过同一个论文编号关联。

总览“近期需关注”和待跟进事项的“全部计划”使用同一份事项列表：包含状态为“待处理”或“跟进中”的事项，也包含未来计划，按事项数量统计。一篇论文可以有多条事项；即使论文已发表、已撤稿或服务已终止，客户、作者的新要求仍可独立新增和跟进。总览按跟进日期从早到晚显示前三条，分别标注已逾期、今天跟进或计划日期，点击“查看全部”进入完整列表。待跟进页顶部展示全部计划、已逾期、今天跟进及未来 7 天的数量。“到期待跟进”仅包含今天及以前的计划，“未来 7 天”仅包含明天至第七天的计划。

在待跟进事项或论文详情的“跟进事项”中新增、编辑内容、日期、状态及备注 / 处理结果。点击“完结”后可补充处理结果并确认，系统记录完成时间，事项退出待办提醒，在“已完成”或“全部事项”中保留。原事项需补充处理时点击“重新打开”；客户或作者提出不同要求时新增事项，分别管理。每次保存都会保留当时的内容、状态和备注，在论文详情中查看处理历史。“已取消”事项单独保留。事项列表按跟进日期、状态及关键词筛选，导出包含处理结果和完结时间。

论文总览提供“已录用”“已发表”快速分类，按每篇论文的当前投稿状态筛选，可继续搜索、按日期筛选及导出。“已归档”是状态分类：在投稿管理中将当前投稿改为“已发表”或“已撤稿”并保存后自动进入；已录用单独归入“已录用”，不计入“进行中”，款项是否结清、经过多少天均不会触发归档。归档记录继续保留在全部记录中；新增改投成为当前投稿后，分类随新状态更新。当前未提供独立的论文手动归档流程。

客户类型分为“同行”“终端客户（自主开发）”“他人推荐”；自主开发终端客户指自己挖掘、直接一对一对接的客户。他人推荐可选填介绍人姓名或来源说明。客户列表提供分类标签、数量和筛选，可与合作状态及关键词组合查询，客户详情、关联客户选择及客户汇总导出同步显示分类。新增和编辑客户时选择类型；旧客户保持“未分类”，待人工确认后补充，保留原有论文和费用关联。分类与介绍人随加密备份保存，旧备份仍可恢复。原分类值“他人介绍”继续兼容读取和保存，页面与导出统一显示“他人推荐”。

论文、客户、投稿及收支保存成功后，自动关闭表单并更新对应列表与统计；保存失败时保留填写内容并提示原因。点击“关闭”或右上角 × 直接关闭抽屉，放弃本次未保存的内容；论文编辑页关闭后返回列表。半包没有写作稿酬，投稿等费用登记为“其他支出”。旧论文保留原有写作流程，按全包兼容读取。

操作结果提示统一使用“保存成功”“新增成功”“删除成功”“改投成功”“刷新成功”等简短表述；导出提示保留记录数量。操作已完成但列表刷新失败时，明确说明操作成功并提示刷新，避免重复提交。

各模块的查询列表统一提供“序号”，按当前筛选与排序结果从 1 连续编号，翻页接续；客户关联记录、投稿详情、收支明细与变更历史也显示序号。CSV 导出增加序号列，原有业务编号及字段保留。序号仅用于当前展示与导出，不作为数据库 ID。操作按钮统一为“新增、编辑、删除、详情、保存”，全包与半包入口分别显示“新增（全包）”“新增（半包）”，原有收支、改投、关联期刊、导出等功能及入口均保留。

各模块共用页面边距、统计卡片、面板、筛选栏和表格样式。序号列统一居中并保持单行，表头和操作按钮不拆字；长论文题目在单元格内换行。窄窗口下各模块继续使用表格，内容超出时仅在表格区域横向滚动，论文管理不再单独切换卡片布局。

表单统一使用“必填”标记，未标记的字段可选；投稿状态为已投稿及后续状态时，实际投稿日期动态标为必填。漏填、格式错误、日期先后冲突、收款定金超过服务费用和写作定金超过稿酬时，在字段下方显示原因，并在保存按钮旁显示醒目提示、定位到首个问题字段。提交失败保留填写内容，可修改后继续保存。表头使用 13px，正文使用 14px，辅助说明使用 12–13px，统一字体并增强对比度。

论文管理列表和详情始终提供删除。确认后删除该论文、投稿、写作安排、全部收支及财务记录、稿件和收支凭证，客户及其他论文保留；终止服务只结束业务并保留这些记录。删除使用版本校验，并重新计算客户统计。

客户信息可记录“合作开始日期”，在新建或编辑客户时填写实际开始合作的日期，支持补录、修改和清空；列表、客户详情及客户汇总导出均包含该日期。它与档案创建时间分别保存，旧客户默认留空，不会推断为建档当天。

投稿时长为实际投稿日至结束/录用日期的天数；未结束计算到当天。已发表的成果另记发表日期。录用、拒稿、撤稿、发表时未填结束日期则自动记录当天；补录历史时可输入真实日期。旧记录没有可靠结束日期时保留未知，不会假定今天为结束日。

写作任务可按状态、客户、开始日期筛选，逾期未交任务单独展示；客户信息支持归档。有论文关联的客户禁止直接删除，可先调整论文归属或归档。

## 已实现

- **论文档案**：题目、作者、客户/委托人、写作者、期刊、投稿系统及网址、投稿日期、跟进日期、备注。
- **账号资料**：投稿账号、投稿密码、绑定邮箱、绑定手机号；密码默认不随档案接口返回，需在详情中点击显示，30 秒后自动隐藏，切换后台时也会隐藏。
- **投稿进度**：草稿、待投稿、已投稿、审稿中、修改中、已录用、已发表、已拒稿、已撤稿；修改期刊、系统、网址、日期或状态时保留变更历史。
- **费用约定**：约定向客户收取的总额、定金及自动计算的尾款，以及约定向写作者支付的稿酬总额、定金及尾款。旧论文的收款定金默认为 0，尾款为原服务费用，不推断历史约定。
- **实际流水**：收取定金、收取尾款、其他收入、支付定金、支付尾款、其他支出，支持多次登记、删除错误流水，记录日期、收付方式和备注。
- **自动统计**：已收、已付、未收、未付、现金净额；金额按整数分存储计算。
- **查询**：按题目、编号、作者、客户、写作者、期刊、系统、账号、邮箱、手机号和备注搜索，支持状态、日期、待跟进和归档筛选及分页。
- **跟进事项**：每篇论文支持多条独立事项，状态为待处理、跟进中、已完成、已取消，支持备注、完结、重新打开和处理历史。旧跟进日期和说明自动兼容为一条待处理事项；仅有日期的记录显示“待补充跟进事项”，编辑时补充内容。论文表单中的跟进日期、说明对应最近的一条未完结事项，清空日期会取消该事项，保留其他事项和历史。旧备份仍可恢复，新事项及处理历史随加密备份保存。MySQL 启动自动执行 V013 迁移，增加独立事项和历史表。
- **导出**：按当前筛选导出 UTF-8 BOM CSV，可用 Excel 打开；台账包含定金、尾款等分类合计，流水可单独导出。CSV 不包含投稿账号、密码、绑定邮箱和手机号；客户汇总导出也不含客户联系方式。备注等自由文本会原样导出，请自行避免在备注中填写敏感信息。
- **备份恢复**：下载完整加密备份并通过界面恢复；恢复需要备份时的密码，替换全部记录，恢复后保留当前系统登录账号与管理密码。
- **访问保护**：新账号注册、账号与密码登录、退出、修改管理密码及账号数据隔离；8 小时会话、HttpOnly/SameSite Cookie、CSRF 校验、登录限流、来源校验、仅监听本机地址。

## 收支计算

例如，一篇论文约定应收 8,000 元，约定稿酬 3,000 元：

1. 先登记“收取定金”2,000 元、“支付定金”1,000 元。
2. 系统显示已收 2,000、未收 6,000、已付 1,000、未付 2,000 元。
3. 后续分别登记收取尾款与支付尾款，系统自动汇总。

未收 = max(0, 约定应收 − 已收定金 − 已收尾款)，未付 = max(0, 约定稿酬 − 已付定金 − 已付尾款)。其他收入、其他支出单独统计，不抵扣合同尾款或稿酬尾款，例如期刊费用不会误抵写作者稿酬。实际定金和尾款合计超过约定时会显示提示，不会阻止记录。累计已收、已付与现金净额包含全部流水；现金净额 = 全部实际收入 − 全部实际支出，不代表最终利润。

收支管理默认展示“应收应付”，按论文列出约定应收、已收定金尾款、待收款，以及约定稿酬、已付稿酬、待付稿酬；即使尚未登记实际流水，也能核对待收待付的来源。点击汇总卡片中的明细入口可查看对应收入、支出或全部流水，或进入论文“收支明细”核对并登记款项。汇总卡片统计全部论文，搜索和流水日期筛选只影响下方明细；应收应付按当前费用约定统计，不使用收支日期筛选。应收应付与实际流水可分别按当前筛选导出。

## 数据位置与备份

实际数据位于项目根目录：

```text
data/
  papers.vault       首个账号或旧版账号的加密数据
  papers.vault.bak   该账号上一次写入前的加密副本
  primary-account.id 首个账号名的 SHA-256 索引，不含密码
  accounts/         其他账号，按账号名 SHA-256 分目录保存独立的 papers.vault
  app.lock           进程锁文件，防止同一数据目录被两个实例同时写入
```

采用 AES-256-GCM 认证加密，使用随机盐和 PBKDF2-HMAC-SHA256（310,000 次）从管理密码派生密钥。论文及账号资料整体加密，采用临时文件写入后替换；每次写入前保留上一份加密数据。已有数据目录不要删除。

在“数据与设置”下载备份；恢复前先下载当前数据。旧备份仍使用当时的密码，即使后来修改了管理密码。紧急恢复 `.bak` 可以通过恢复窗口选择该文件，或先关闭服务、另存当前文件后，再用备份替换 `papers.vault`。

每个账号最多 10,000 篇论文，每篇最多 1,000 笔流水；每个加密数据文件最大 8MB，单笔及约定金额最大 100 万元。数据量增大时适合后续迁移到关系数据库。旧版仅使用管理密码的数据文件，首次用原密码及新账号登录时会绑定该账号；其后必须使用绑定账号登录。旧版根目录加密文件没有账号索引时，需要原账号先登录一次以建立索引，之后可以继续注册新账号，原加密文件不移动。恢复备份只替换当前账号的记录，不更改登录账号和密码。将另一账号的备份导入 MySQL 时会重新分配业务 UUID 并保留内部关联，避免与原账号记录冲突。数据目录可通过 `-Dapp.data=绝对路径` 指定，静态资源根目录可通过 `-Dapp.root=项目绝对路径` 指定。

当前版本支持多账号独立使用，程序仅监听 `127.0.0.1`；可按部署说明通过 SSH 隧道或 Nginx HTTPS 反向代理远程访问，不含团队共享空间、多人角色分工、附件上传、自动抓取期刊状态和邮件/短信提醒。投稿账号密码为人工登记，不会登录外部期刊系统。登录后的解密数据和密钥会保留在服务进程内存中，退出会撤销浏览器会话；关闭服务会释放进程内存。

## MySQL 存储

MySQL 模式沿用现有的客户、论文、投稿、收支及备份界面，业务数据分别保存在关联表中。每个注册账号拥有独立的工作空间和空间管理员身份，所有业务查询与修改绑定当前会话所属空间。旧账号保留原空间与数据；其他角色和团队共享授权尚未启用。服务仍只监听本机。

1. 准备 MySQL 8.0.16 或以上版本，将官方 MySQL Connector/J 驱动 JAR 放入 `lib/`，下载方式见 [驱动说明](lib/README.md)。第三方 JAR 不提交到仓库，新克隆项目需要自行准备。
2. 将 `config/application.example.properties` 复制为 `config/application.properties`，填写数据库地址、端口、库名、账号和密码，并设置 `app.storage=mysql`。真实配置已加入忽略列表，不要提交连接密码。
3. 双击 `start.cmd` 启动。启动器已包含 `lib/*` 的驱动路径；IDEA 项目也已配置 `lib` 目录作为依赖。手动启动时使用以下命令：

   ```powershell
   javac -encoding UTF-8 --release 17 -d out src/*.java
   java -cp "out;lib/*" Main
   ```

数据库不存在时，程序会尝试创建指定数据库；也可以由管理员预先创建。首次启动执行 [V001 初始化脚本](db/mysql/V001__initial_schema.sql)，只创建 `lw_` 前缀表，不删除已有表。数据库连接账号需要该库的建表、索引、外键及业务读写权限；自动建库还需要建库权限。脚本记录 SHA-256 校验，执行过的脚本不要直接修改。数据库连接失败时会停止启动，不会自动改写到文件存储。

升级时自动执行 [V002 合作开始日期脚本](db/mysql/V002__customer_cooperation_date.sql)，在 `lw_customer` 增加可为空的 `cooperation_started_at DATE` 字段，保留所有原客户数据。连接账号还需要该表的 `ALTER` 权限。该业务日期不做时区转换。

[V003 服务类型脚本](db/mysql/V003__paper_service_type.sql) 为 `lw_paper` 增加 `service_type`，区分全包和半包；旧论文默认全包以保留写作记录，半包不生成 `lw_writing_task`。该升级需要 `lw_paper` 的 `ALTER` 权限。

[V004 客户收款定金脚本](db/mysql/V004__customer_payment_deposit.sql) 为 `lw_paper` 增加 `contract_deposit_cents`，以整数分保存约定收款定金，并约束其不超过服务费用。旧记录默认 0，原服务费用与实际流水保留；约定尾款实时计算，无需单独存储。该升级需要 `lw_paper` 的 `ALTER` 权限。

[V007 客户分类脚本](db/mysql/V007__customer_classification.sql) 为 `lw_customer` 增加 `customer_type` 和 `referrer`，分别保存客户类型与可选介绍人。旧客户字段默认为空，页面显示“未分类”；升级保留客户、论文与收支。该升级需要 `lw_customer` 的 `ALTER` 权限，支持中断后继续执行。

配置优先级为 Java `-D` 参数、环境变量、配置文件、默认值。支持 `APP_STORAGE`、`DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USERNAME`、`DB_PASSWORD`、`DB_SSL_MODE`、`DB_KEY_FILE`；可用 `-Dapp.config=配置文件绝对路径` 指定配置文件。远程数据库应使用可信证书和 `VERIFY_IDENTITY`；本机 MySQL 若提示 RSA 公钥获取受限，可配置受信任的 TLS，或仅在受信任的本机连接中设置 `db.allowPublicKeyRetrieval=true`。

### 旧文件迁移

切换前先停止旧服务并下载加密备份。MySQL 中尚无本系统成员且 `data/papers.vault` 存在时，登录页会要求使用原账号和管理密码。成功验证后，程序会：

- 在 `data/backups/pre-mysql-日期时间.vault` 保存原始加密文件副本；原 `papers.vault` 保持原样。
- 在一个数据库事务中导入客户、论文、写作、多次投稿、凭据、收支及历史，保留业务 UUID 和金额。
- 将原账号设为当前空间管理员，并记录导入文件的 SHA-256。后续登录读取数据库，不重复导入旧文件。

原密码或账号不正确不会导入；数据库已初始化时，不会用旧文件覆盖现有账号和业务记录。空数据库且没有旧文件时，首次打开仍由用户设置账号与管理密码，没有默认应用账号或密码。导入后，在界面核对论文和客户数量、已收已付及投稿记录，再使用数据库继续工作。

### MySQL 数据保护与回退

登录密码保存为带随机盐的 PBKDF2-HMAC-SHA256 哈希；投稿密码使用独立 AES-256-GCM 密钥加密，并绑定对应投稿 UUID。客户资料、题目、账号名称和金额等业务列按关系型数据库的常规方式保存，并非整库加密。默认密钥位于 `data/database.key`，可用 `db.keyFile` 指定。**备份数据库时必须同时保管对应密钥文件**；密钥缺失或不匹配时服务会拒绝启动，不能用新密钥替换已有数据库的密钥。

“下载加密备份”仍生成与文件模式兼容的 `.vault`，业务数据和投稿密码整体加密，可通过恢复界面在两种模式之间迁移。恢复只替换业务记录，保留目标安装的登录账号和管理密码。修改管理密码不改变数据库的独立投稿密钥，旧备份仍使用下载备份时的密码。单份备份导入仍限制为 8MB，当前论文与流水数量上限保持不变。

如需回退，可先下载 MySQL 模式中的最新加密备份，停止服务，设置 `app.storage=file` 后启动，再从界面恢复该备份。直接切回文件模式只会读取之前保留的文件，不会自动包含迁移后新增的数据库记录。不要同时运行两个模式来维护同一套业务。

## 升级与多人上线准备

旧版 schema=1 数据在登录时自动升级为 schema=2，保留原有账号、密码、论文、收支及投稿历史，并从原客户名称生成关联客户、从原投稿字段生成一条投稿记录。升级前文件保留在 `data/papers.vault.bak`；旧版备份恢复时也会转换。当前版本的客户、写作和多次投稿都会进入完整加密备份。

后续多人上线的角色矩阵、数据库表关系、空间隔离、字段权限、密钥拆分及迁移验收见 [多人上线设计](docs/多人上线设计.md)。当前已经提供 MySQL 关联存储及旧文件迁移，尚未启用多人权限和用户管理；远程访问按部署说明配置 SSH 隧道或 HTTPS 代理。切换存储不等于获得多人角色隔离。
